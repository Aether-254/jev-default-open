# 先验证普通用户路径，再设计高权限集成

状态：已接受，2026-09-27。

早期方案把整个 Broker 自动提权，并将原生、IM 和模型集成都当作即将可用；这会把低权限来源的打开请求送进高权限启动器，同时掩盖尚未完成的真实客户端验证。当前决定取消自动提权与默认 Hook 启动，保留同一 Windows 用户、普通完整性级别的手动启用路径，分别验证离线 UI、加密状态、原生所有权和实际客户端，代价是暂不覆盖高权限应用。

后续只有在 Broker IPC 身份验证、允许的请求/目标以及非提权 launcher 的边界独立完成并通过测试后，才重新评估提权方案。fixture、编译或协议测试的通过不得写成 Jev 在线准确率、QQ/微信真实聊天兼容性或全桌面覆盖的证明。

默认原生构建另以 `JEV_ENABLE_EXPERIMENTAL_HOOK=OFF` 禁用注入，`open_hook.dll` 保持透传，Host 明确拒绝启用；MSVC 显式 ON 分支必须独立构建/验证后才能进入受控桌面测试。QQ 的认证 bridge transport/当前版本 trusted adapter 未生产接线，微信没有具体 `VerifiedVisibleContextReader` 实现，二者必须按「仍需补实现」记录，而不能包装成只差现场验收。
